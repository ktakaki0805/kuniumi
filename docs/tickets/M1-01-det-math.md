# M1-01 Deterministic math functions via libm

- Status: done
- Milestone: M1
- Depends on: none
- Crates: kuniumi-math
- Design: プロジェクト方針 / 規約の要点
- Decisions: D-08, D-10, D-11

## Goal

`kuniumi_math::det` provides `sin`, `cos`, `sin_cos`, `tan`, `atan`, `atan2`,
`asin`, `acos`, `exp`, `ln` and `pow` with bit-identical results on every
platform, so later code can use them without breaking seed reproducibility.

## Scope

In:
- Dependency `libm` (pure-Rust port of musl's libm, itself mostly FreeBSD
  msun; licence MIT) in `kuniumi-math` only, pinned to the latest version at
  implementation time: `libm = "=0.2.16"`. It never calls the platform's math
  library.
- Thin `#[inline]` wrappers in `det`, each with a doc comment stating its
  accuracy: what its msun source documents (if anything) and the maximum error
  measured against the exact value.
- A decision on `default-features`: keep libm's architecture-specific paths
  only if every function they replace is an exactly specified operation (sqrt,
  fma, rounding); otherwise disable them. Record the reasoning in the module
  documentation.
- The first Python tools (D-11): `tools/det_reference.py` (mpmath, correctly
  rounded reference values) and `tools/det_error.py` (error against the exact
  value, through the example `crates/kuniumi-math/examples/det_eval.rs`),
  Python pinned in `mise.toml`, `mpmath` pinned in `tools/requirements.txt`, a
  short `tools/README.md`, and the virtual environment `tools/.venv`
  git-ignored.

Out:
- Hyperbolic and other functions (added when a stage needs them).

## Implementation notes

- An upgrade of `libm` can change the last bits of some results. That is why
  the version is pinned and why golden tests exist: an upgrade is treated like
  any other potentially world-breaking change (conventions, "World-breaking
  changes").
- `default-features`: libm 0.2.16's `arch` feature (on by default) replaces,
  on x86/x86_64 with SSE2, `sqrt` (`sqrtsd`) and `fma` (`vfmadd`/FMA4 chosen
  at run time, else the soft fma); on aarch64 with NEON, `sqrt`, `fma` and
  `rint` (`frintn`). All of these are exactly specified by IEEE 754, so the
  results equal the soft versions bit for bit; `arch` is kept. The x87 `exp`
  paths exist only for x86 without SSE, which kuniumi does not support, and
  they are selected regardless of features. Cargo feature unification could
  re-enable `arch` through another crate anyway, so disabling it would not be
  a reliable guarantee.
- `sin_cos` wraps `libm::sincos`, which uses the same argument reduction and
  kernels as `sin` and `cos`; the bitwise equality is tested.
- API (all `#[inline] pub fn`, radians, argument order as std):
  `sin(x)`, `cos(x)`, `sin_cos(x) -> (f64, f64)`, `tan(x)`, `atan(x)`,
  `atan2(y, x)`, `asin(x)`, `acos(x)`, `exp(x)`, `ln(x)`, `pow(x, y)`.
- Files: `crates/kuniumi-math/src/det.rs` (wrappers and module docs),
  `src/det/tests.rs` (tests), `src/det/golden.rs` (generated by
  `tools/det_reference.py`, not edited by hand), `examples/det_eval.rs`
  (evaluates `det` on inputs from standard input, for `tools/det_error.py`).
- Accuracy documentation: msun's sources state "nearly rounded" for `sin`,
  `cos`, `tan` and `pow`, an error "always less than 1 ulp" for `exp` and
  `log`, and nothing for `atan`, `asin`, `acos` and `atan2`. The documented
  numbers are measured by `tools/det_error.py` against mpmath (10⁶ inputs per
  function, error in ULPs of the exact value's binade, the 20 worst cases of
  each function rechecked at 600 bits).
- The test module may call std functions as a reference with
  `#[allow(clippy::disallowed_methods)]`.
- Accuracy test: inputs from `Rng::from_seed` (deterministic). Error is the
  distance in ULPs between `det::f(x)` and std's `f(x)`, measured on the
  integer line of ordered bit patterns (±0 coincide; both NaN counts as 0; one
  NaN fails). Ranges, 10⁶ inputs each unless stated:
  - `sin`, `cos`, `tan`, `sin_cos`: uniform in [−10⁵, 10⁵], plus 10⁵ inputs
    `k·(π/2)` (|k| ≤ 63 661) moved by up to 2¹⁶ ULPs;
  - `atan` (an inverse trigonometric function, not named separately): uniform in
    [−10⁵, 10⁵], plus 10⁶ log-uniform magnitudes in [2⁻⁶⁰, 2⁶⁰] with random
    signs;
  - `atan2`: random signs and log-uniform magnitudes; half with independent
    exponents over the whole normal range, half with the exponents of y and x
    within 64 of each other;
  - `asin`, `acos`: uniform in [−1, 1];
  - `exp`: uniform in [−745, 709];
  - `ln`: log-uniform over all positive finite doubles (uniform bit patterns,
    so subnormals are included), plus 10⁵ uniform in [0.5, 2];
  - `pow`: x half uniform in (0, 10⁶] and half log-uniform in [2⁻²⁰, 10⁶],
    y uniform in [−50, 50]; plus 10⁵ inputs with integer y in [−50, 50].
  The test prints, per function, the maximum error, the number of inputs with
  0 and 1 ULP error, and the worst input.
- Golden tests: `tools/det_reference.py` computes each value with mpmath at 256
  and at 512 bits, checks that both round to the same double, and rounds to the
  nearest double (ties to even, subnormals included) through Python's exact
  `Fraction` → `float` conversion. It also records on which side of that double
  the exact value lies. Inputs are fixed in advance (small, medium and huge
  arguments, e.g. `sin(1e22)`); the script writes `golden.rs` with input bits,
  correctly rounded result bits and the side. libm is not correctly rounded,
  so at a few inputs it returns the other double next to the exact value. The
  tests list those inputs per function (`*_FAITHFUL`) and expect exactly that
  other neighbour there, and the correctly rounded value everywhere else;
  every expected bit pattern therefore comes from the script, while the list
  itself is recorded from libm 0.2.16 like a fingerprint. The scheme assumes
  libm is faithfully rounded at each golden input, which holds for all 106.
  The script also provides the correctly rounded constants used by the
  special-value tests (π, π/2, π/4, 3π/4).
- Output fingerprints: in addition, an FNV-1a hash of the output bits of every
  function over 10⁴ fixed inputs is recorded once the accuracy, special-value
  and reference golden tests pass. It catches a change in the last bit of any
  result (a libm upgrade, a platform difference) that the hundred or so golden
  inputs would miss.
- Python 3.14.10 (the mature 3.14 line) in `mise.toml`, `mpmath==1.4.1` (the
  latest stable release) in `tools/requirements.txt`.
- The accuracy test compares with the platform's libm. Locally that is glibc;
  CI later also runs it on macOS and Windows, whose libms are not correctly
  rounded either, so a 1-ULP bound against std there is likely but not
  guaranteed. If it fails there, the bound or the reference changes in a
  follow-up; the golden and fingerprint tests are the determinism checks.

## Acceptance criteria

- [x] Accuracy: over 10⁶ random inputs per function, the maximum error against
      std is ≤ 1 ULP. Ranges: trigonometric functions over [−10⁵, 10⁵] plus
      inputs near multiples of π/2; `atan2` over random signs and magnitudes;
      `asin`/`acos` over [−1, 1]; `exp` over [−745, 709]; `ln` log-uniform;
      `pow` with x ∈ (0, 10⁶], y ∈ [−50, 50]. The measured maximum per function
      is reported. (`det::tests::accuracy_*`)
- [x] Golden tests: bit patterns for at least 8 fixed inputs per function, from
      the independent reference script; inputs where libm is only faithfully
      rounded are listed explicitly. (`det::tests::golden_*`)
- [x] Special values: ±0, ±∞ and NaN for every function; C99 Annex F cases for
      `atan2` and `pow`; `sin_cos(x) == (sin(x), cos(x))` bitwise.
      (`det::tests::special_*`, `det::tests::sin_cos_*`)
- [x] Output fingerprints of all functions over 10⁴ fixed inputs are recorded
      and checked in debug and release. (`det::tests::fingerprints_match_recorded`)
- [x] `libm` is listed in the D-10 table, and `cargo tree -p kuniumi-math`
      shows `libm v0.2.16` as its only dependency.
- [x] `mise run ci` passes.

## Result

What was done:
- `kuniumi_math::det` gained `sin`, `cos`, `sin_cos`, `tan`, `atan`, `atan2`,
  `asin`, `acos`, `exp`, `ln` and `pow`, `#[inline]` wrappers over
  `libm = "=0.2.16"` (MIT), each documenting its msun source, what that source
  states about accuracy, and the measured maximum error against the exact
  value. The module documentation records the `arch` decision and the
  accuracy table.
- `tools/det_reference.py` (mpmath 1.4.1, Python 3.14.10 pinned in
  `mise.toml`) generates `src/det/golden.rs`; `tools/det_error.py` measures
  the error against mpmath through the example `examples/det_eval.rs`;
  `tools/README.md` explains how to run both; `tools/.venv` is git-ignored.

Deviations from the plan:
- The first plan rejected golden inputs whose exact result lies within
  0.05 ULP of a rounding midpoint and expected libm to round all others
  correctly. Running the tests showed that msun is not correctly rounded:
  `exp(1.0)` returns 2.7182818284590455 (one ULP above the correctly rounded
  `E`), likewise `exp(−10)`, `ln(3)`, `tan(1e22)` and `pow(123.456, 2.5)`. The
  midpoint filter was dropped (the original, natural inputs were restored), the
  script now records the side of the exact value, and the tests list these 5
  of 106 inputs and expect the other neighbour there. Choosing other inputs to
  avoid them would have hidden a real property of the functions. The golden
  acceptance criterion was reworded to match ("inputs where libm is only
  faithfully rounded are listed explicitly"); the owner approved this changed
  criterion and method as is, after review round 1 (finding R1-2).
- The fingerprints were collected into one test,
  `fingerprints_match_recorded`, which reports every changed function at once.
- Review round 1 showed that the first accuracy documentation ("error below
  1 ULP" for every function) was wrong: msun states no bound for `atan`,
  `asin`, `acos` and `atan2`, and `atan2` exceeds 1 ULP. The documentation now
  rests on a measurement against the exact value, for which
  `tools/det_error.py` and `examples/det_eval.rs` were added.

- Golden: `golden_*` (11 tests) pass; 10–12 inputs per function, 106 in all,
  e.g. `sin(1e22) = −0.8522008497671888`, `sin(π) = 1.2246467991473532e−16`,
  `exp(−740) = 4.2e−322` (subnormal), `ln(5e−324)`. 101 equal the correctly
  rounded value, the 5 listed ones its faithful neighbour. Regenerating with
  the script reproduces `golden.rs` byte for byte (`diff` empty).
- Special values: `special_sin_cos_tan`, `special_atan`, `special_asin_acos`,
  `special_exp`, `special_ln`, `special_atan2` (all 11 groups of F.9.1.4 plus
  NaN) and `special_pow` (all 19 rules of F.9.4.4, including
  `pow(±0, −∞) = +∞`, stated explicitly since C11; plus NaN, overflow and
  underflow) pass.
- Fingerprints: `fingerprints_match_recorded` passes with identical values in
  debug and release, and also with libm's `force-soft-floats` feature
  (`cargo test -p kuniumi-math --features libm/force-soft-floats det`, debug
  and release, all 31 `det` tests pass), which confirms that the `arch`
  instructions do not change any result.
- `cargo tree -p kuniumi-math` shows `libm v0.2.16` only; `libm` is in the
  D-10 table (unchanged, it was already listed for M1-01).
- `mise run ci` passes: fmt, clippy `-D warnings`, tests in debug and release,
  MSRV 1.85.0, cargo-deny (advisories, bans, licences, sources ok).
- Run time: the whole `det` test module takes 0.29 s in debug and 0.11 s in
  release (wall clock, tests in parallel).

Review: 2 rounds.

  against mpmath (`tools/det_error.py`, `examples/det_eval.rs`) and quoting the
  measured maxima. R1-2 minor, the golden criterion and method changed after
  refinement; the owner approved them as is. R1-3 nit, NaN results in the
  `sin_cos` test were compared bit for bit; now only required to be NaN.
- Round 2 (APPROVE): R2-1 minor (module doc still said the maxima against std
  were in each function's documentation; the atan2 sample range was not
  stated) and R2-2 nits (an unwrapped ticket line; "1–12 %" should be
  "0.2–12 %") were fixed. R2-3 nit: `CLAUDE.md` and D-23 list the tools pinned
  in `mise.toml` without the Python pin this ticket adds (D-11 anticipates

  instructions changed.
